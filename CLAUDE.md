# Vektplan — notes for Claude

Personal iPhone web app for Emil (Norway). Plain HTML/CSS/ES modules, no build step, hosted on
GitHub Pages from `main` (https://extricl4.github.io/Vektplan/). Installed via Safari "Add to Home Screen".

## Who it's for
- Sensitive stomach and nausea for years, follows low-FODMAP, gets full fast, has food anxiety, wants to gain weight gently and get stronger.
- Tone everywhere: calm, warm, no guilt. Never suggest restriction, skipping meals, weight loss or "burning off" food.
- Don't invent calorie targets. The daily goal is optional and set by the user (ideally with a doctor/dietitian). Calm mode hides numbers.
- Recipes/foods must stay low FODMAP per Monash guidance; flag anything uncertain as "check".

## Design
"Daylight": light stone-grey background `#E6E9E7`, off-white cards `#F4F5F3`, calm sky-blue accent, Figtree font,
rounded organic shapes. A dark "Midnight" theme exists. Tokens are CSS variables in `css/app.css`.
UI text is bilingual: `tr('English', 'Norsk')` and `L({ en, nb })`.

## Releasing an update (always do this when changing the app)
1. Make the change.
2. `python3 tools/bump.py X.Y.Z "English notes" "Norske notater"` — bumps `js/version.js`, `version.json`, and `sw.js` (version + offline file list).
3. Commit and push to `main`. The app shows "Update ready"; Settings → Update now installs it.

If you add a new file under `css/`, `js/`, `fonts/` or `icons/`, the bump script picks it up automatically.

## Layout
The page never scrolls: `#app` is a full-height flex column, each `.screen` scrolls inside it and the
`.tabbar` is a normal row at the bottom. Don't go back to `position: fixed` bars or `window.scrollTo`
(iOS 26 home-screen apps misplace fixed bars after the keyboard). Use `nav.scrollTo(y)` / `nav.scroller()`.
Every tab screen must end with `${tabbar('<tab>')}` after its `.screen`.

## Food and training
- Food amounts: `js/data/amounts.js` gives every food everyday units (`slice`, `glass`, `dl`, `piece`…) plus grams;
  `js/amount.js` turns them into items `{ src, fid, name, units, amount, unit }` with `itemKcal`, `itemFodmap`
  (portions above Monash low-FODMAP limits become "moderate"), `amountSheet()` and `packItem()`/`restoreItem()` for saving.
- There is no meal plan in the UI any more (he asked for that): food is a diary. He logs what he ate, how much and when;
  Today and Food → Diary show calories, protein, fat and carbs, a timeline, and ideas on the side (`js/ideas.js`, never orders).
  Macros: `js/data/macros.js` ([protein, fat, carbs] per food portion / recipe serving); logs store `mac` for one portion,
  `portion` scales it; `js/nutrition.js` has `logMac`, `dayTotals`, `logItems` (the one way to save a log). Old logs without
  macros count as "unknown". `profile.goalProtein` is optional and only set by him (suggestion: 1.6 g/kg).
  Meal slots and `planner.js` still exist for reminders, streaks and the coach; logs get the nearest slot by time.
- Logging (`js/views/log.js`, route `log`, `log/<date>`, `log/type`, `log/photo`) is a meal builder: every food tapped becomes an
  ingredient row with an editable amount + unit; the whole meal is saved as ONE log via `logItems`. Typing an amount updates
  numbers in place (`refreshNumbers`), never a full re-render (that would swallow the next tap on iOS).
- Base foods: `js/data/foodbase.js` is generated by `tools/foodbase.py` from Matvaretabellen 2026 (Mattilsynet, NLOD;
  github.com/mattilsynet/matvaretabellen-deux). `NUTRITION[id] = [mvtId, kcal, protein, fat, carbs, fibre, sugar]` per 100 g,
  `BASE_FOODS` adds raw/dry/cooked variants with `pair` (the raw/cooked twin). Don't hand-edit it; change the script and re-run.
- He asked for NO saved meals and NO shopping list: they're gone from the UI. `myMeals`/`shopping` stay in storage only so old data
  survives. Don't bring them back.
- Charts: `js/views/charts.js` (`dayChart` one stacked bar per day: protein/carbs/fat/unknown energy, protein grams under it;
  `macroBar`). Colours are `--c-protein`, `--c-carbs`, `--c-fat`, `--c-unknown`.
- Supplements: `supps.list` (`js/supps.js`) with `n` per day, `unit` (gummy, tablet, capsule…) and `each` ("1 g").
  Counts per day in `days[key].suppN[id]`; `days[key].supps[id]` is set when the day's count is reached (old days only have that).
  `since` on an entry keeps older days from counting it. Protein powder adds one food log per scoop with `supp: id`.
- Trends: `js/history.js` builds one summary per day from what's stored; nothing extra is saved.
- Training plans are in `training` (`js/training.js`). Ready-made programs (`js/data/programs.js`) store session items with a
  `slot` (squat, push, row…) plus `lo`/`hi` rep range; `resolveList()` turns slots into exercises for the place
  (`currentPlace()`: today's pick or `training.place`) and the equipment ticked in `training.equip[place]`. Items you swapped
  yourself stay as they are. Places are `home` and `gym` (old `dumbbells` is migrated to home + dumbbells).
  Sessions: `{ id, name, groups, ex: [{ id, sets, reps, slot?, lo?, hi?, focus? }] }`, `schedule[weekday] = sessionId`,
  `extras[weekday] = 'walk'|'stretch'`. Empty `training.sessions` = the built-in Strength A/B rhythm.
  `workoutDef(id)` gives one shape for own sessions, built-in ones and walks. Workouts save `log[exId] = [{ r, kg }]`.
- Programs: start2, focus3 (full body + a focus day for his chosen muscles, default biceps + core), full3, ul4.
  Focus muscles: chest, back, shoulders, biceps, triceps, legs, glutes, core (old "arms" → biceps + triceps via `normFocus`).
- How-to for exercises: `js/data/howto.js` (what you need, steps split by "|", a tip) and `js/views/howto.js`
  (`howToSheet`, `needsLine`). Every exercise a program can pick must have an entry. The guide screen is `#/guide`.
- Default level is "gentle" (he eats very little): 2 sets, max 5 exercises (6 with a focus), 90 s rest, no heavy barbell lifts
  auto-picked, nothing that presses on the stomach (crunches, leg raises) auto-picked.

## Apple Watch
Web apps can't read HealthKit. A Shortcut (guide in `js/views/health.js`) copies Health samples as
`Type;Start;End;Value;Unit` lines; `js/health.js` parses them (English/Norwegian names, ISO or default
dates) into `health.days[YYYY-MM-DD]`. Sleep counts for the day you wake up.
"Get data from the Watch" opens `shortcuts://run-shortcut?name=…`; coming back offers "Bring it in" (clipboard needs a tap).
Best setup: a daily Shortcuts automation (Run Immediately) runs it each morning, then Today's Watch card shows a Paste button.

## Data
All user data is in `localStorage['vektplan.v1']` (see `js/store.js`). Keep changes backward compatible:
add fields with defaults in `defaults()`; never rename existing ones without a migration in `migrate()`.
